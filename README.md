# PAPAS 7.0 풍차돌리기 실전 관리 앱 (v3)

백테스트기의 매매 규칙을 그대로 써서, Stage마다 **오늘 넣을 주문**을 계산하고 실제 체결을 기록하는 앱입니다.
증권사 주문은 실행하지 않습니다.

## 포함 파일
| 파일 | 내용 |
| --- | --- |
| `app.py` | Streamlit 화면 (오늘 할 일, 대시보드, Stage 관리, 거래 원장, 신호·차트, 백테스트, 설정) |
| `strategy.py` | 매매 규칙 계산 모듈. 실전 화면과 백테스트가 함께 씀 |
| `supabase_schema.sql` | DB 테이블·보안 정책. 처음 설치와 이전 버전 업그레이드 모두 이 파일 하나로 |
| `requirements.txt` | 실행 패키지 |
| `excel_stages.csv`, `excel_transactions.csv` | 기존 엑셀(1~7th Stage, 거래 45건)을 옮긴 가져오기 파일 |

## 1. Supabase
1. SQL Editor에서 `supabase_schema.sql` 전체 실행 (이전 버전을 이미 실행했어도 그대로 다시 실행)
   - 기존 거래의 `일반 매수`는 `재매수`로, `Make up 매수`는 `1차 메이크업`으로 바뀝니다.
2. Project Settings > API에서 Project URL과 anon(publishable) key 복사
3. **Authentication > URL Configuration의 Site URL을 Streamlit 앱 주소로 변경**
   (기본값 localhost:3000이면 가입 인증 메일 링크가 앱으로 돌아오지 않습니다)

## 2. GitHub · Streamlit Community Cloud
1. 저장소 최상위에 `app.py`, `strategy.py`, `requirements.txt`를 올립니다 (`strategy.py`가 꼭 같이 있어야 합니다)
2. Main file은 `app.py`
3. Secrets:
```
SUPABASE_URL = "https://프로젝트ID.supabase.co"
SUPABASE_ANON_KEY = "anon 또는 publishable key"
```
service_role 키는 절대 쓰지 말고 GitHub에도 올리지 마세요.

## 3. 처음 사용
1. 회원가입 → 이메일 인증 → 로그인 (첫 로그인 계정에 SOXL 기본 계좌가 생깁니다)
2. **설정**에서 초기 보유수량·평단가·초기 현금·1회 수량·간격표·메이크업 규칙 확인
3. 엑셀 기록을 옮기려면 **거래 원장 > CSV 가져오기**에서 `excel_stages.csv`와 `excel_transactions.csv`를 함께 올리고 가져오기 (한 번만)
4. 매일 **오늘 할 일**에서 주문을 확인하고, 체결되면 그 자리에서 체결 입력

## 매매 규칙 (strategy.py)
1. **최초 매도:** 출발일부터 5거래일, 매일 종가 MOC로 1회 수량씩. 미국 휴장일은 자동으로 건너뜁니다.
2. **기준가:** 총 매도대금 ÷ 매도수량
3. **등비 재매수:** n차 지정가 = 기준가 × (1 − 간격)^n, 매도가 끝난 다음 거래일부터 주문
   - 간격 기본값은 Stage 순서별 5% → 4.5% → 4% → 3.5% → 3%, 이후 3% (설정에서 변경)
4. **1차 메이크업:** 확정 주봉의 몸통 하단(시가·종가 중 낮은 값) > 5주선
   → 신호 다음 거래일부터 5거래일 종가 LOC, 예산 = 매도대금 × 50% − 이미 쓴 매수금액
5. **2차 메이크업:** 1차 이후, 30주선이 전주보다 낮지 않고(횡보·상승) 몸통 하단 > 30주선 (5·30주선 골든크로스)
   - 30주선이 하락 중이면 적용하지 않습니다 (원문에서 '아주 중요'로 강조)
   → 5거래일 종가 LOC, 예산 = 매도대금 − 쓴 매수금액 − 진행 중인 1차 잔여예산
6. 메이크업 신호가 뜨면 오늘 할 일에 판정 근거와 함께 표시되고, **신호 확인**을 눌러야 주문 지시가 나옵니다.
7. 주봉은 금요일(또는 그 주 마지막 거래일) 장 마감으로 확정된 것만 씁니다.

### 설정에서 바꿀 수 있는 규칙 (기본값은 백테스트 방식)
| 항목 | 기본값 (백테스트) | 다른 선택 |
| --- | --- | --- |
| 1차 신호 | 5주선 위에 있음 | 5주선 아래에 있다가 회복 |
| 2차 신호 | 30주선 횡보·상승 + 몸통 > 30주선 (원문) | 30주선 횡보·상승 + 몸통 > 300주선 (이전 기본값) / 일봉 몸통 > 30일선 (엑셀 방식) |
| 메이크업 크기 | 금액 기준 (매도대금의 50%·100%) | 수량 기준 (매도수량의 50%·100%, 엑셀 방식) |

백테스트 메뉴에서 세 규칙을 바꿔 가며 결과를 비교한 뒤 설정을 정하세요.

## v3에서 바뀐 점
- **2차 메이크업 기본 규칙 수정:** 원문 OCR의 '300평선'은 '30이평선'을 잘못 읽은 것이었습니다. 기본 규칙을 `weekly30`(30주선 횡보·상승 + 몸통 하단 > 30주선)으로 바꿨습니다.
- 이전 규칙(`weekly300`)은 비교용 선택지로 남겼습니다.
- `supabase_schema.sql`을 다시 실행하면 저장된 `weekly300` 설정이 `weekly30`으로 바뀝니다. 300주선 규칙을 일부러 고르셨다면 실행 후 설정에서 다시 고르세요.
- 신호·차트 표에 '2차 조건(30주선)' 열을 추가했습니다.
- **원금 회복 지표 추가:** 설정에 '초기 보유분 평단가'를 입력하면 대시보드에 원금, 원금 회복률, 원금까지 필요한 상승률, 손익분기 주가를 보여 줍니다. 손익분기 주가를 평단가(그냥 보유했을 때의 본전 가격)와 비교해 전략 효과를 볼 수 있습니다.
  - 원금 = 초기 보유수량 × 평단가 + 초기 현금, 원금 회복률 = 현재 평가액 ÷ 원금, 손익분기 주가 = (원금 − 현재 현금) ÷ 현재 보유수량
  - 백테스트 결과에도 '원금 회복률(%)'과 '손익분기 주가($)' 열을 추가했습니다.
  - `supabase_schema.sql`을 다시 실행해야 평단가 칸(`initial_avg_price`)이 생깁니다.
- 백테스트 결과 저장 키 충돌 오류(`st.session_state['bt']`)를 고쳤습니다.
